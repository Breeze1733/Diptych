# File transfer and public clipboard backend

This service owns the file transfer station and public clipboard. Clipboard records are independent of Diptych's private diary data and uploaded media.

Run `npm ci --ignore-scripts`, then `npm start`. The existing PM2 process is `transfer-backend`.

| Environment variable | Default |
| --- | --- |
| `PORT` | `3001` |
| `TRANSFER_UPLOADS_DIR` | `transfer-backend/transfer-uploads` |
| `CLIPS_DIR` | `transfer-backend/clips` |

`GET /clips`, `POST /clips`, `PUT /clips/:id`, and `DELETE /clips/:id` preserve the original public clipboard API and JSON records (`content`, `preview`, `createdAt`). IDs accept 1–128 ASCII letters, digits, `_`, or `-`, including all IDs generated by the original service. `/transfer-api` is also accepted as a request prefix.

Nginx must route both the exact `/api/clips` path and its `/api/clips/` children to this process, rewriting them to `/clips`. Keep the existing `/transfer-api/` and `/uploads/` routes. Restrict the sibling Diptych backend to private APIs; it must no longer register clipboard routes.

For migration, copy the existing backend's `clips/*.json` into this service's `clips/` directory while public clipboard writes are paused. Preserve filenames and contents. Do not move either service's upload directories. Deploy `server.js`, `package.json`, and `package-lock.json`, preserve runtime data, run `npm ci --ignore-scripts`, and restart `transfer-backend` before re-enabling clipboard requests.

The lockfile includes compatible security updates for Multer 2.4.0, proxy-addr 2.0.8, and qs 6.16.1. Multer's minimum version is raised to the patched release; Express remains at 5.2.1.

The clipboard is intentionally public. Clipboard IDs and upload filenames are validated as single files, symbolic links are rejected by file operations, and clipboard writes use a synced temporary file followed by an atomic rename. Never configure the two runtime directories to point into private diary storage.
